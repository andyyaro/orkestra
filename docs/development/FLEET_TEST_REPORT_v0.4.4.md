### agents-picker
Installed orkestra-runtime 0.4.4 via uv, ran it through a sanitized PATH with zero real agent CLIs visible, and exercised `orkestra start --agents ...` across 10 variants: known-but-unsigned pairs, all four alias spellings, duplicates, mixed case, whitespace, empty string, unknown names, fake practice-agent names, a single valid name, and totally unknown vendor names. The practice-mode fake agents (ada, grace) are correctly NOT addressable via --agents ada,grace - good design, matches doc's claude/codex/antigravity/gemini set. Overall the flag's parsing/validation logic is solid, but the ordering bug (repo creation before hard-fail check) is a genuine defect a real user would hit on first try in a fresh directory.

### nested-dev
I set up orkestra-runtime 0.4.4 in a sanitized-PATH sandbox and worked through the nested-repo guard scenarios end to end. The guard itself is solid: running `init` or `start` in any subdirectory of an existing repo (shallow, a/b/c deep nesting, or a git worktree/submodule that git itself resolves as its own toplevel) gives a clear, well-worded refusal with exit 1 and zero filesystem mutation (verified with `ls -la` before/after). The suggested remedy - literally copy-pasting `orkestra start <repo-root>` from the error message - worked perfectly, even auto-falling back to a friendly practice-mode setup when no real agent CLIs were signed in. I then completed the full start(init)->run->review->accept journey at the repo root on a repo with real prior git history, using a hand-edited `adapter = "fake"` config to drive the built-in practice agents (since no fake claude/codex/agy stubs were provided in bin/); the whole pipeline (plan, parallel isolated worktrees, review-and-repair cycle, integration, accept --yes) worked flawlessly and produced a clean, well-labeled 'practice run' commit into main. The `orkestra demo` command is a great zero-setup way to see the same lifecycle. The one real gap I found: the nested-repo guard is only wired into `init`/`start` - if a `.orkestra/` directory somehow already exists inside a repo subdirectory (stale leftover, hand-copied config, older orkestra version, etc.), `doctor`, `status`, and presumably `run` do not detect the nesting at all and silently proceed as if it were a normal top-level project, even printing "repository: ok" pointing at the wrong (sub)directory.
